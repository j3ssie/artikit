[field notes] text-mode charts

Charts made of characters

The text charts page draws twenty-two charts without a canvas or a plotting library. Each one is a few lines of text in a <pre>. This post goes through the five kinds of character it uses, and the three things that had to line up before they looked like charts.

Why draw in text

The Workbench dashboard draws its bars by repeating one character, █, and colouring the run. It looks like terminal output because it is terminal output: the bar is text, so it selects like text, copies like text and grows with the font.

The text charts page takes that one idea and asks how far it goes. It goes as far as twenty-two charts, with one exception. The ring of the donut is an SVG circle, because no character draws an arc.

A bar that is text selects, copies and scales like text.

Whole blocks make bars

A bar is a count scaled to a width in characters, rounded, and repeated. The whole of it is one line, kept from the Workbench as it was written:

The last part matters. A value that rounds to nothing still prints one light shade, so a small count never reads as a missing row.

A bar built this way is accurate to one character. On a scale 40 characters wide that is 2.5% of the longest bar, which is enough to rank rows and not enough to read a value. So every bar prints its number beside it.

Eighth blocks make columns

Turned upright, one character per row is far too coarse. Unicode has seven partial blocks, ▁▂▃▄▅▆▇, that fill a cell from the bottom in eighths. With the full block that is eight levels in every row, so a column chart nine rows high resolves 72 levels.

A stacked column needs one more rule, because a character can only be one colour. A cell takes the colour of the segment that crosses its middle, and the top cell takes the colour of the top segment.

Box-drawing makes lines

A line uses six box-drawing characters: ─ │ ╭ ╮ ╰ ╯. It holds its level until the next point, then turns through a rounded corner, runs up or down, and turns again. Each series is rounded to one of ten rows.

Where two lines cross, both characters show. That is the one place the charts stop being plain text: copy the figure and the series come out one after the other, not overlaid.

Shades make heat

Three shade characters and the full block give four densities: ░ ▒ ▓ █. A grid of them reads as a heat map with no colour ramp at all, which also means it survives a monochrome terminal.

Three things that had to line up

Width in characters

Nothing on the page is positioned in pixels. Before a chart is drawn, the script puts 40 block characters in a hidden <pre>, measures them, and divides the width of the panel by the width of one. That number, cols, is all a chart is given. When the panel changes width the chart is laid out again, and on a long range the days are grouped into buckets until they fit.

Rows that touch

Full blocks join vertically only if a line is exactly as tall as the glyph. A line height of 1.5 leaves gaps. The font's own line height closes them, but it is rarely a whole number of pixels, and the fraction shows as hairline seams. So the script measures the glyph and sets the line height to that height rounded down to a whole pixel. Rows then overlap by less than a pixel, in the same colour, where nobody can see it.

Bars that end together

A bar that shows shares of a whole has to be exactly as wide as the bars around it. Rounding each segment on its own can leave the row a character short or a character long. Instead the widths are rounded down, and the characters left over go to the segments with the largest remainders.

What colour is for

Colour is the one thing a character cannot carry by its shape, so it is spent only on identity. A single series is the accent. Scan modes are blue and orange. Classes take four further hues, and severity runs from red to grey. Each set was checked on the dark ground and on the light one for how far apart its neighbours stay under the two common forms of colour blindness.

The check is a floor, not the plan. Every chart also says its numbers in text: a count beside each bar, a line under the chart that reads out the cell under the pointer, and the same figures as a table behind a [table] button. All the characters in use are listed here.

[NOTE]The pages load no web font. They ask for JetBrains Mono, Fira Code or Cascadia Code and fall back to the system's monospace, so a chart's letters, digits and blocks come from one font and share one width.

Checklist

  1. Measure the width in characters, with the character you will draw.
  2. Round to whole characters once, at the end, and give the leftovers to the largest remainders.
  3. Use eighth blocks wherever one row is too coarse.
  4. Set the line height from the glyph, in whole pixels.
  5. Print the number next to the mark.
  6. Keep the table one click behind the chart.

The dataset behind the figures is generated in the page from a fixed seed: 180 days of sample findings, with nothing real in it. Change the seed and every chart on the text charts page follows.
