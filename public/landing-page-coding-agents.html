the fleet

Ten tasks do not queue behind one.

▸Sessions run in parallel. Each has its own worktree and container, so they cannot step on each other.
▸The router picks the model. Small edits go to a small model and hard ones escalate. Pin one if you prefer.
▸Automations run on a schedule. Nightly dependency bumps, a weekly sweep for flaky tests.
▸Budgets stop runaway work. A time cap and a spend cap per session, checked before every step.
▸Every action is logged. Commands, diffs and model calls are kept with the pull request.
▸Local or hosted. The same CLI drives your laptop or a pool of runners.
